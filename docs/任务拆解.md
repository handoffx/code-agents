# 任务拆解

前提：[验证能力决定粒度](验证能力决定粒度.md)；判定标准：[任务单元四条件](任务单元四条件.md)；按 [分级规则](分级规则.md) 决定走流程的哪几步。

## 按验证方式分三类

### 1. 探索型：产出是知识，不是代码

- 例："现在的鉴权是怎么串起来的？""三种方案各要改哪些地方？"
- 验证：读完答案后，你能不能做出决策
- **允许写原型，但交付物是结论和 [决策清单](决策清单.md)，不是代码**
  - 原型只用来给清单提供证据，比如"方案 A 试过了，在 X 处会卡住"
  - 原型代码默认丢掉
  - 真正要保留的代码，按决策清单重新走一遍流程，不让探索阶段的代码未经审批混进代码库

### 2. 保持行为型：重构、搬迁、铺路

- 验证：现有测试全部通过，**且断言一行不改**。只允许机械性改动（改名、改导入路径），这些改动单独列出来给你看
- 最适合交给 agent，因为验证是现成的、客观的
- Kent Beck："先让改动变容易，再做那个容易的改动。"前半句就是这类任务

### 3. 改变行为型：新功能、修 bug

- 验证：先有一个会失败的测试或检查，再去实现
- **测试由你写或由你审过**，实现交给 agent。否则就是 agent 自己出题自己判卷。偏向自己写，能保住"想清楚什么是对的"的能力（见 [技能退化](技能退化.md)）

一个真实的功能需求，通常拆成：探索 → **写出整体验收的检查（此时失败）** → 若干保持行为的准备 → 一个很小的行为改变 → **让整体验收通过**（见 [完成定义](完成定义.md)）。行为改变那一步往往小得出人意料，这是好事。

## 顺序原则

- **整体验收的检查放在第一步**，其余步骤按下面的原则排
- **不确定性高的先做**：先验证最可能推翻方案的那一步
- **每一步结束时系统都能跑**：优先纵向切片（端到端的一条细线），少做横向切片（中间状态无法验证）
- **先定接口，再写实现**：契约（类型签名、接口、数据结构）是决策，在 [决策清单](决策清单.md) 里由你定；实现是执行，交给 agent

## 失败信号：两次纠正规则

**同一任务纠正 agent 两次还不对，就停下来，不要纠正第三次。**

- 反复纠正说明拆错了，而不是执行错了：任务里藏着没暴露的决策，或者上下文不够
- 继续纠正只会把上下文越弄越乱。机制上的解释：上下文只分配不释放，走错的弯路会一直留着并累积（见 读书：Agentic Engineering 第 4 章）
- 做法：丢掉这次会话 → 回到拆解 → 把暴露出来的决策显式做掉 → 开一个干净的任务
- 丢掉之前，把走不通的方案和原因记进 [任务文件](任务文件.md)；新会话从任务文件接着做
- 丢掉会话后，有时自己调试，不要每次都重开 agent（见 [技能退化](技能退化.md)）
- 预防：让模型在执行中主动暴露新决策，而不是等你纠正两次才发现，见 [决策清单](决策清单.md) 的补充规则

## 做到八成：补完还是丢掉

（待争论问题 第 18 题；书中称为沉没成本困境，见 读书：Beyond Vibe Coding 第 10 章）

**两难之所以难，是因为高估了已有代码的价值。** 那八成代码重新生成很便宜；贵的是一路上得到的决策和教训，而它们存在 [任务文件](任务文件.md) 里，丢掉代码不会丢掉它们。

| 剩下的两成 | 处理 |
|---|---|
| **只是执行**：知道要做什么，只是没做完 | 补完，可以从任务文件开新会话接着做 |
| **有没暴露的决策**，或方向错了（"连贯的错误"：开头误解了需求，后面每一步都在强化它） | 丢掉代码，保留任务文件；把新暴露的决策补进决策清单，回到拆解 |
| **补完的代价超过任务的价值** | 整个放弃，等于回到"值得做吗"重新问一次 |

- **预算**：agent 提出的或价值不高的任务，在回答"值得做吗"时顺便定一个预算（如"最多值一小时"），到了预算还没做完就按第三类处理（见 [分级规则](分级规则.md)）
- 按小步验收，本来不该一次性交来一大块做到八成的成果。实际出现时多数是**后台长时间自主运行的任务**，一般丢掉
- L0、L1 任务没拆解、做到八成卡住，说明分级判断低了，按升级信号处理

## 大上下文，小步验收

拆解不等于切小会话。给模型完整的目标和背景，同时要求它在每个验证节点停下来交证据。见 [两个旋钮](两个旋钮.md)。

## 让模型拆，由你来批

- 人在动手前拆解时，掌握的信息最少。所以先做探索型任务，让模型了解代码后再提拆解方案
- **审决策比审代码便宜得多**
- 审批时不问"这些步骤合理吗"，而是问：每一步怎么验证？有没有我在意的决策被它悄悄做掉了？
- 风险：容易沦为走过场。解法是先让模型列出 [决策清单](决策清单.md)，逐项表态后再出拆解方案
