# 并行多 agent

> 并行的瓶颈是**你的工作记忆**，不是 agent 的数量。频繁切换 agent 等于你自己的上下文在频繁切换，最后忘了哪个 agent 在干哪件事。来源：待争论问题 第 5 题。

## 为什么不按数量限制

你的时间花在需要你判断的环节：[决策清单](决策清单.md) 表态、[审查层](审查层.md) 的判断层、[完成定义](完成定义.md) 里由你确认的部分。agent 写代码不占你的时间。所以：

- 瓶颈在你时，并行只会让待审队列更长；判断做到一半被拉走，更容易"批了但说不清为什么"（见 [技能退化](技能退化.md)）
- 并行真正有用的是填补你等 agent 的时间
- 实际同时跑几个 agent 要看任务，数量本来就不固定。要限制的是同时占用你脑子的那一个

## 规则

1. **复位卡**：agent 每次停下来等你（等表态、等审、卡住），先给一张复位卡，你读完就能接上，不用回忆：
   - 任务目标：一句话
   - 现在在哪：拆解方案第几步，共几步
   - 为什么停：等表态 / 等审 / 卡住
   - 需要你做什么：具体到一个动作
   - 你之前定过的：相关决策一两条
2. **按阶段限制**：
   - 后台任务不限数量：执行中、探索中，或只需过证明层的 L0、L1
   - **同一时间只有一个任务处在需要你判断的阶段**
3. **按自己的节奏切换**：做完手上的判断，再处理下一个在等你的 agent。agent 停下来等不会出错，只是慢一点。

复位卡和 [上下文层](上下文层.md) 是同一个道理：持久的东西不能只放在聊天里，人的记忆也一样。L2 及以上的任务，复位卡放在 [任务文件](任务文件.md) 开头，直接从文件读，不从聊天记录临时拼。

## 适合与不适合并行

- **适合**：探索型任务（交付物是结论）、L0 和 L1、互相不碰同一块代码的任务
- **不适合**：两个 L2 或 L3 同时等你表态或审查；碰同一块代码的任务（两个任务之间的缝比步骤之间的缝更难发现，见 [完成定义](完成定义.md)）
- **同一个 worktree 同一时间只有一个任务在改代码**。要并行就另开 worktree；开始新任务时如果当前 worktree 已有进行中的任务，先问你：接着做那个、在新 worktree 开新任务，还是确认不碰同一块代码后继续（2026-10-28 做插件时确定）

书中作者的上限约 5 个，限制在于能为几个合并结果担责（见 读书：Agentic Engineering），与本篇按"需要你判断的环节"来限制的思路一致。
