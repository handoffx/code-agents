# 两个旋钮

> 拆解任务时要调两个互相独立的旋钮：**验证粒度**和**决策委托**。它们受不同因素限制，出问题时方向相反，不能用同一个动作去修。

## 起因

待争论问题 第 1 题：细粒度拆解和"少约束、多信任模型"冲突吗？反方最强的论点有三条：

1. **人拆解时掌握的信息最少**：在对代码了解最少的时候就把任务切好了
2. **切片会丢掉全局最优**：子任务只看到局部，问题到集成时才暴露
3. **人为的任务结构也是一种规则**，同样会受"过度约束损害表现"这条规律影响

这三点都成立。问题出在"细粒度拆解"同时指了三件事。

## 三个维度

| 维度 | 含义 | 应该由谁定 |
|---|---|---|
| **执行上下文** | 一次会话里，模型能看到多少 | 尽量大：给全目标、全背景 |
| **验证节点** | 在哪里停下来、拿出证据 | 由**你的验证能力**决定 |
| **决策归属** | 哪些决策必须由你拍板 | 由**你对模型判断力的信任**决定 |

反方的论点主要打在"执行上下文"上。把它和另外两项分开，冲突就消解了。

## 两个旋钮

### 验证粒度旋钮

- 受限于**你的验证能力**，即发现 + 回退 + 证明（见 [验证能力决定粒度](验证能力决定粒度.md)）
- "出错会伤到谁"不是第三个旋钮，而是通过发现和回退体现在这个旋钮上
- 模型变强**不会**让它自动变粗
- 拧得太松的症状：质量不行、审不过来
- 详见 [验证能力决定粒度](验证能力决定粒度.md)

### 决策委托旋钮

- 受限于**你对模型判断力的信任**
- **模型进步真正拧动的是这个旋钮**：能放心交出去的决策越来越多，需要事先拍板的越来越少
- 拧得太紧的症状：规则越写越多、模型表现反而变差，也就是 Anthropic 说的"过度约束"（见 Agent 与 Harness）
- 拧得太松的症状：模型悄悄做掉了你在意的决策

## 实践：大上下文，小步验收

给模型完整的上下文，同时要求它小步交验：

完整的提示词见 [方法论总览](方法论总览.md) 的统一提示词模板：先列决策清单，确认后再拆解，每完成一步停下来给出验证证据，遇到新决策停下来问。

> 原先这里的提示词是"先提出拆解方案，等我确认后再动手"，写于 [决策清单](决策清单.md) 之前。2026-10-28 按 待争论问题 第 14、15 题改为引用统一模板。

模型拿到的是全貌，你在每个节点上都握有否决权。

针对"人拆解时信息最少"：**让模型拆，由你来批。** 先做探索型任务，让模型了解代码后再提出拆解方案。审批时只看两件事：

1. 每一步怎么验证？（验证粒度旋钮）
2. 有没有哪个我在意的决策被它悄悄做掉了？（决策委托旋钮）

为了防止审批走过场，先让模型列出 [决策清单](决策清单.md)，逐项表态后再出拆解方案。
