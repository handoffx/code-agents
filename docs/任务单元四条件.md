# 任务单元四条件

| 条件 | 自检问题 | 不满足时的症状 |
|---|---|---|
| **可验证** | 能不能写出一个检查，通过就说明完成了？ | agent 自己宣布完成，你半信半疑 |
| **无未定决策** | 执行步骤里还有没有*你*在意、但没定下来的决策？ | 方向跑偏，或做了你不想要的取舍 |
| **上下文自足** | 能访问仓库的新同事，不问你能不能做完？ | agent 靠猜补全意图 |
| **可审查** | 契约层面的变化（新接口、新抽象、新依赖、模块边界）是否少到你能对每一条说出判断理由？ | 你开始"扫一眼就过" |

## 无未定决策

最常被忽略的一条。**拆解的单位是决策，不是代码行数。**

任务里可以有很多决策，但凡是你在意结果的，都要在执行之前通过 [决策清单](决策清单.md) 定下来。交给 agent 执行的，应该只剩"怎么做都行"的部分。执行中冒出新的决策，按补充规则停下来加进清单，不能自己做掉。

> 原为"决策单一"（你在意的决策最多一个），写于决策清单之前。2026-10-28 按 待争论问题 第 14 题改为现在的说法。

## 可验证

对每一步适用，也对**整个任务**适用：每步验证都通过不等于整个任务完成，整体验收见 [完成定义](完成定义.md)（2026-10-28，待争论问题 第 17 题）。

## 上下文自足

缺的上下文怎么补，看它是不是每个任务都需要：每个任务都需要的，写进常驻规则文件（[上下文层](上下文层.md) 的准入测试）；只有这个任务需要的，写进指令。Claude Code 官方加规则的触发条件里也有"新同事需要同样的上下文"（见 调研：规则文件官方建议）。

## 可审查

审的是契约，不是 diff（见 [审查层](审查层.md)）。diff 的大小交给证明层；你要能对每一条契约变化说出判断理由，和 [决策清单](决策清单.md) 里"同意要能说出一句理由"是同一个门槛。

> 原为"产出能不能一口气审完"，无法度量。2026-10-28 改为现在的说法。
