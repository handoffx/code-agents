# 验证能力决定粒度

> 任务粒度由你的验证能力决定，而不是模型能力。

**修正（2026-10-28）**：这条命题只描述了**验证粒度旋钮**。模型进步拧动的是另一个旋钮，即**决策委托**。完整模型见 [两个旋钮](两个旋钮.md)。

## 验证能力的定义

**验证能力 = 发现 + 回退 + 证明**（2026-10-28 扩展，见 待争论问题 第 9 题）：

| 组成 | 问题 |
|---|---|
| 发现 | 出错了多快能发现？ |
| 回退 | 能多干净地撤销？ |
| 证明 | 用什么证明它是对的？ |

原来只考虑了"证明"（测试、类型、契约）。"出错会伤到谁"不单独作为维度：它本身无法直接操作，能操作的是发现和回退。比如支付账本的危险在于错误发现得晚、钱付出去收不回来；加上影子账本对账、可撤销的交易，风险等级就会真的下降。

## 论证

- 模型越强，它**能完成**的任务越大
- 但你**能确认它完成对了**的任务大小并没有跟着变
- 真正的约束是两者中较小的那个，而它几乎总是验证能力

## 推论

- 想交出更大的任务，办法不是写更详细的 prompt，而是先提升验证能力：证明（测试、类型、契约）、发现（可观测性、告警、对账）、回退（可撤销、灰度、特性开关）
- **拆解和验证是同一件事的两面**
- 动手之前的检验：能不能写出一条命令或一个检查，通过就说明任务完成了？写不出来，这个任务就还没准备好交给 agent
- 副作用：小任务天然好审，审查瓶颈大半来自 diff 太大，而不是审查者不够

审查深度同样按这个定义分配，见 [审查层](审查层.md)。
