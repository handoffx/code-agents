# task-contract:resume

任务文件的意义在于：新会话不需要用户凭记忆重新交代，也不会推翻已经定下的决策、重走已经证明走不通的路。

参数：$ARGUMENTS

## 1. 选任务

参数给了任务文件路径就直接用。否则运行 `agent-tasks list`，它列出本仓库所有 worktree 里未完成的任务（标题、级别、状态、进度、更新时间、所在 worktree、文件路径）。

- 没有未完成任务：告诉用户，问是否要开始新任务（task-contract:start）；用户想看已结束的任务时用 `agent-tasks list --all`
- 有任务（哪怕只有一个）：用选择框让用户挑，每个选项写明标题、状态、进度和所在 worktree。只有一个时也确认一次，避免接错任务

选中的任务不在当前 worktree 时，告诉用户这个任务的代码在另一个 worktree，建议到那个目录开会话再 resume（在这里改，改的是另一份代码）。用户坚持时再继续。

## 2. 读任务文件

读完整个文件，尤其是：

- **决策**：已定的不要重新讨论。用户的表态就是契约；有"取代 Dn"的以后来的为准
- **已排除的方案**：不要再走一遍。确实需要重新考虑时，先说明理由，作为新决策请用户表态
- **拆解与进度**：找到下一步

再读 `${CLAUDE_PLUGIN_ROOT}/skills/start/SKILL.md`，后续执行、复位卡、证据和完成报告都按它的规则。

## 3. 对照代码核对进度

任务文件可能落后于代码（上个会话改了代码但没来得及更新文件），也可能超前（记成已验证，代码后来被改过）。用 `git status`、`git log` 和相关文件核对：

- 标为"已验证"的步骤：重新跑它的验证命令。证据必须晚于最后一次修改，上个会话的结果不能代表现在
- 不一致时以代码和实际运行结果为准，更新任务文件，并告诉用户哪里不一致

## 4. 接着做

给出复位卡，更新任务文件的 status 和 updated，从下一步继续。上次是 `blocked`（比如因为两次纠正丢掉了会话），先看"已排除的方案"和新补的决策，确认用户已经对新决策表态再动手。
