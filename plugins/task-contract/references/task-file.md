# 任务文件结构

用 `agent-tasks new <简短英文名> --title "<标题>" --level L2|L3` 新建，命令会生成下面的结构。各部分写入方式不同，原因是性质不同：复位卡和进度描述"现在在哪"，可以覆盖；决策和已排除的方案描述"发生过什么"，丢一条就可能让新会话重走弯路或推翻用户定过的事，所以只追加。

```markdown
---
title: <任务标题>
level: L2 | L3
status: waiting-decision | waiting-review | active | blocked | done | abandoned
created: YYYY-MM-DD HH:MM
updated: YYYY-MM-DD HH:MM
---

# <任务标题>

目标：<写成可观察的结果>
预算：<如有>

## 复位卡
<!-- 每次停下来时重写 -->
进度：第 N 步 / 共 M 步
为什么停：等表态 | 等审 | 卡住
需要你做：…
相关决策：…

## 决策
<!-- 只追加。改主意就新加一条，写明"取代 Dn" -->
### D1. <要决定什么>
- 可选方案：A. … / B. …
- 倾向：A，因为 …
- 选错的代价：…
- 依赖的系统事实：…
- 表态：待表态
- 表态：同意（2026-10-28）— <用户的一句理由，如有>

## 已排除的方案
<!-- 只追加 -->
- <方案>：<为什么行不通，证据是什么>

## 拆解与进度
<!-- 状态可以更新；已验证的步骤不能悄悄改回未完成，确需重做时写明原因 -->
1. [已验证] 写出整体验收检查（当前失败）
   - 验证：`<命令>` → `<关键输出>`
2. [进行中] …
   - 验证方式：…
3. [未开始] …
N. [未开始] 让整体验收通过，交付文档等非代码产出

## 已知缺口
- …
```

决策清单一列出来就整份写进"决策"，每项标"待表态"；用户表态后在该项下追加一行"表态：…"，不改动原来的内容。

frontmatter 的 `status` 和 `updated` 每次停下来都要更新：`agent-tasks list` 和会话开始时的提示靠它们判断哪些任务没完成、哪个最近在做。"进度："那一行也会显示在列表里，写成一眼能看懂的样子。
